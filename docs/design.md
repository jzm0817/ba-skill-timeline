# ba-skill-timeline 技术设计

本文描述拟实施方案。业务验收以 `requirements.md` 为准，实施状态见 `progress.md`。

## 1. 架构

| 层 | 技术与职责 |
|---|---|
| 领域 | Python 3.11+，负责角色配置、FIFO、费用校验、分组与导出。可独立运行 pytest，无需接入视频或启动 Web 服务。 |
| 媒体 | PyAV 与 FFmpeg 负责解码、时间轴和媒体格式处理。OpenCV 与 NumPy 负责 ROI、模板匹配、进度条测量和帧间比较。OCR 通过可替换接口接入。 |
| 服务与存储 | FastAPI 提供视频、标定、分析任务、审核、重算和导出接口。SQLite 保存任务和修订状态，JSON 作为可迁移的分析快照，大型证据写入 `BA_DATA_DIR`。 |
| 界面 | React、TypeScript、Vite。用 HTML5 Video 与 Canvas 预览视频、框选 ROI 和定位证据。Playwright 覆盖标定、审核、导出及录制相关流程。 |

优先验证传统视觉方案。运行时与依赖版本在各阶段建立工程入口时锁定。单机任务以任务 ID、分析版本和修订号区分，同一修订只读取一套完整结果。重算完成后用事务切换当前版本，失败保留上一个可用版本，避免界面读取半套结果。

## 2. 数据契约

下表列出初始字段，具体类型和序列化版本随实现验证。

| 记录 | 主要字段与含义 |
|---|---|
| `VideoAsset` | `video_id`、`source_kind`、`relative_path`、媒体格式、尺寸、时长和时间基信息。 |
| `RoiProfile` / `FrameRef` | ROI 配置版本、归一化矩形及适用画面。帧引用包含 `video_id`、原始 PTS、时间基、相对播放时间和必要的帧序号。 |
| `Observation` / `EvidenceRef` | 观测 ID、类别、时间或有效区间、槽位、ROI、候选读数、置信度、识别器版本和证据 ID。证据包含帧引用及可选的相对截图路径。 |
| `ReleaseEvent` | `event_id`、片段、发生区间、槽位、状态、`cost_before`、`required_skill_cost`、角色候选、补位候选、证据 ID 和待审原因。状态区分候选、确认、否决及冲突。 |
| `CycleSnapshot` | 关联事件和修订号、可达状态集合、逐位置可确定身份、约束证据与冲突信息。状态集合元素为三槽位和三项有序队列。 |
| `RecoveryEdge` / `ReleaseGroup` | 相邻事件 ID、恢复量或可证明的范围、判定、阈值、证据和断组原因。分组含有序事件 ID，分别记录自动结果和人工修订。 |
| `ReviewRevision` | 目标对象、基准版本、修正前后值、原因、来源和时间。保留原始分析，并派生新的事件和快照版本。 |

Cost 运算使用十进制精确值，JSON 初步采用十进制字符串保存已知值，未知为 `null`。测量误差较大时保存上下界与方法。来源字段区分机器观测、规则推导和人工确认，置信度只用于筛选和审核，不能代替来源。JSON 包含 `schema_version`、分析器版本、配置快照和稳定引用。

## 3. 分析流程

1. 校验 `BA_DATA_DIR` 及输入文件，媒体层读取元数据。以 PTS 和时间基定位画面。时间戳缺失或异常时保留异常状态。按比例配置 ROI，裁剪前校验边界，分辨率、宽高比或有效画面变化时重新核对标定。
2. 第一阶段粗扫筛选疑似槽位变化、Cost 下降和视频不连续区间，保留各信号的候选窗口。第二阶段按原始帧和前后文复核，并合并重复窗口。保留可疑区间和取样配置，以便评估粗扫漏检。
3. 读取释放前 Cost、释放时有效技能费用和补位候选，核对帧序与多帧证据。扣费动画滞后时区分释放时刻和扣费可见时刻，观测不足则待审。确认释放与确认角色身份分别记录。
4. 按已确认的释放顺序重放 `SkillCycle`，根据有效补位约束更新历史与当前候选。无法确认中间是否漏放、事件先后或跳剪前后是否连续时，暂停跨边界推理，待人工补齐事件或确认新片段初始状态。
5. 从已确认事件和 Cost 时间序列计算恢复量及分组。将输入、观测、推导与证据写入可复核的分析版本。审核更新后从受影响的事实重算，再检查并导出正式 Markdown。

## 4. 核心模块

### `SkillCycle`

完整已知模式从一个状态开始。部分未知模式对剩余角色枚举三阶全排列，初始化六个候选。校验可见槽位、队列长度和角色集合，拒绝重复、越界及缺失角色。

对每个候选和每个已确认释放，先取得该槽位原角色，再以队首替换该槽位并把原角色放到队尾。按可靠观测过滤预期补位。例如初始可见 `[1,2,3]`，左槽释放后若确认补入 `5`，则原初队首为 `5`，还剩两种候选。低置信候选留作证据。确定身份来自所有存活路径对同一事件或同一位置的一致结论。

候选路径保留初始排列及事件快照索引，使后续过滤可回溯早期释放角色。硬约束使候选归零时记录冲突，保留最后有效快照供审核，并暂停把下游身份发布为确定结论。人工更正后从初始状态重放。Phase 1 优先全量重放，测试通过后再考虑检查点优化。

### `CostReader`

输入带时间戳的数字和进度条 ROI。输出两路原始读数、融合候选、有效区间及证据。用数字模板或可替换 OCR 读取数值，用校准后的条长估计细粒度变化。根据前后帧建立稳定区间。两路矛盾、遮挡或校准失效时保留证据和未知状态。

### `SkillCostReader`

读取带槽位的技能费用 ROI，以多帧一致性和卡面有效区间约束输出。费用绑定槽位与时间，换卡、减费或遮挡时重新判定。释放校验只使用覆盖释放点的有效观测或审核记录。费用边界不确定且可能改变校验结论时待审。

### `SlotEventDetector`

利用槽位 ROI 的卡面变化、选中状态、消失与稳定补位，结合 Cost 变化给出释放候选的时间窗和槽位。窗口级复核排除短暂选中、取消与过场变化。按证据和费用约束确认，记录排除或待审原因。多个槽位同时出现变化且先后不明时保留候选。

### `ReplacementCardRecognizer`

在补位动画稳定后对卡面 ROI 提取模板相似度或局部特征。模板由角色编号关联，可来自标定或人工确认截图。输出排序候选、分数、时间窗和证据。只有达到经验证的可靠度或人工确认的身份才成为 FIFO 硬约束。

### `ContinuousReleaseGrouper`

恢复量估计先使用连续观测、扣费时点和已验证的恢复量口径。如果可验证区间内仅有恢复和上次释放扣费、无截顶和其他变动，可由下次释放前 Cost 减去上次释放前 Cost 与当时实际扣费之差求得恢复量。条件无法核实时保留未知。分组器只消费可证明的恢复结果，恢复量或可信范围的上界严格低于阈值才连组。跨阈值、证据不足和断片按需求处理。人工修订和自动边界分别保存。

### `MarkdownTimelineExporter`

输入已审核至可导出的事件序列、最终分组及显示名称。先校验序列、身份和组首 Cost，再清理名称中的分隔性空白，并在清理后为空时回退编号。按组连接，使用 UTF-8 和 LF，末尾写一个 LF。成功时以完整文件替换目标，校验或写入失败时保留原有导出，JSON 始终可独立生成。

## 5. 持久化与浏览器录制

源视频放入 `videos/`，标注、证据及输出分别写入 `annotations/`、`evidence/`、`outputs/`。相对路径在访问前解析并校验位于 `BA_DATA_DIR` 下。审核与重算以修订号检测并发冲突。导出记录对应的分析版本和分组修订，JSON 中的证据可以独立定位。

录制界面由用户主动启动，经浏览器共享选择和授权后录制选定的标签页。本地服务接收录制数据并写入临时文件，停止后检查媒体可解码性，再生成正式视频引用。保留实际录制容器，先验证能否直接走统一解码流程。浏览器范围、音频和转封装需求列为 Phase 5 决策。

## 6. 待确认的产品决策

1. `0.5c` 分组中的恢复量是否包括技能额外返还的 Cost，以及 Cost 到达上限后未到账的理论回费是否计入。建议先按实际到账的自然恢复设计，影响口径且证据不足时保留未知，Phase 3 前确认。
2. Phase 5 首批需支持哪些 Windows 浏览器，是否需录制标签页音频，是否要求将录制文件另存为 MP4。建议先验证 Chrome 或 Edge 的视频录制及原容器分析。
3. 初次真实验证优先覆盖哪些战斗模式、分辨率和界面设置，是否可提供一段允许本机使用的视频及人工标注。样本可在 Phase 1 视频验证时接入，识别与准确率目标在取得基线后确认。
4. 确认无释放的分析是否需要正式导出。建议保留 JSON 并提示无释放，避免生成只有空行的 `timeline.md`。Phase 3 前确认。
