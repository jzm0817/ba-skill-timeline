# ba-skill-timeline 项目需求

依据 `AGENTS.md`、现有进度模板和本次项目启动要求整理。本项目是本地 Web 应用，从《蔚蓝档案》战斗视频提取技能释放顺序和释放前 Cost，保留可复核的证据并生成 `timeline.md`。

## 1. 视频输入和环境

- 支持读取 `BA_DATA_DIR/videos/` 中的本地 MP4，以及用户主动授权录制的浏览器标签页视频。两种来源进入同一分析流程，录制来源和媒体格式随视频记录保存。
- 录制提供开始、停止和保存状态。取消、拒绝授权、捕获结束或保存失败时明确提示结果，已成功保存且可解码的片段可单独分析。录制和分析在本机完成，未经授权不向第三方传送媒体。
- 分析前检查数据目录、视频可读性和解码能力。数据盘缺失、文件缺失、格式不支持时显示可操作的错误。源视频只读，证据、标注与输出单独存放。持久化路径相对 `BA_DATA_DIR`，两台 Windows 电脑可各自配置盘符。
- 用户可标定和预览 Cost 数字、进度条及三个槽位的卡面和费用 ROI。时间定位使用实际视频时间戳，保存足以定位证据的帧信息。跳剪、时间戳异常及遮挡应标记并供审核。

**验收**　可分析本地 MP4 和授权后保存的受支持录制文件。取消授权不产生有效分析任务。移动硬盘换盘符后原有相对引用仍可读取。硬盘缺失时给出明确错误。已知画面位置的测试素材可按实际时间戳预览指定 ROI。

## 2. 角色、初始顺序与释放检测

- 固定六个稳定角色编号 `1–6`。编号独立于技能位置。用户可按编号填写名称，缺省、`null` 或纯空白名称使用编号。改名只影响显示及导出，重复名称可提示歧义。
- 初始可见槽位按从左到右配置三个互异角色。另三个角色可按等待顺序配置，也可仅从角色全集推得集合，保留全部六种可能排列。每个状态中六个编号恰好各出现一次。
- 一次成功释放记录该槽位原角色，等待队首填入该槽，原角色进入队尾，另外两个槽位保持原样。可靠补位观测、角色唯一性及后续事件可逐步缩小候选范围。结论只在剩余候选一致时确定，其来源须可追溯。补位冲突、释放顺序不明或片段衔接不明时进入审核。
- 分别识别资源 Cost 数字与进度条、三个槽位当前的实际技能费用、释放槽位及补位卡牌。动态费用按释放当时的有效证据确定。`cost_before` 为释放前资源，`required_skill_cost` 为当时费用。两值可用且满足 `cost_before >= required_skill_cost` 是确认释放的必要条件，另外还需多帧释放证据，例如卡牌选中、消失、补位或 Cost 变化。只有确认的释放推进状态。费用不足、未知、证据不足、遮挡或跳剪附近的冲突均保留供审核。未知数值使用 `null`，保存原始观测与推断依据。

**验收**　已知初始状态的 FIFO 变化符合三槽不变量。未知初始状态产生六种候选，并随相容观测缩小，矛盾证据可定位，候选事件无法推进状态。费用相等且证据齐全的释放可确认，费用不足、未知或仅有 Cost 变化的事件待审核。改名后可以直接重新导出。

## 3. 恢复量和连续分组

- 对时间顺序相邻的已确认释放，使用上次释放后至本次释放前的实际恢复量判断。默认阈值为 `0.5c`，支持配置。严格小于阈值时同组，等于或大于时分组断开，相邻关系可传递。
- 回费效果、费用减免、Cost 上限、扣费动画延迟和额外消耗均需结合证据解释。恢复量无法证实时，记录未知并默认断组待审。视频跳剪强制断组。待确认事件影响相邻关系时，断组待审。人工可合并或拆分有连续性的组，并保留理由和原自动判断。

**验收**　相邻恢复量 `0.49c` 同组，`0.50c` 和 `0.51c` 分组断开。连续两段低于阈值的三次释放同组。未知恢复量和跳剪断组，自动结果与人工修正分别可查。

## 4. 人工审核与持久化

- 界面可定位原始视频和证据帧，区分原始观测、自动推导、人工确认和冲突。支持确认或否决候选，修正释放槽位、顺序、身份、费用、资源 Cost、初始顺序及分组，记录修正前后值和理由。
- 修正上游事实后按视频顺序重放，重新计算受影响的队列、身份、恢复量和分组。更正后仍无法解决的矛盾继续待审。保留历史修订、原观测及证据关联。
- JSON 包含视频、ROI 和分析配置版本、所有候选与确认事件、原始 Cost 和技能费用观测、角色候选与队列快照、证据引用、恢复量、分组及审核历史。证据引用可定位来源视频、时间戳、ROI 和可用的截图。未知数值序列化为 `null`。

**验收**　可由 JSON 中的事件追到原始观测与证据。修正一条早期事件后，下游重放结果与从头按相同审核记录重放一致，历史观测可查。将数据目录整体迁移后，JSON 的相对路径仍能定位证据。

## 5. 正式导出

- 文件名固定为 `timeline.md`。每组独占一行，组首为 `{cost}c {角色名称或编号}`，`c` 后一个 ASCII 空格。组内后续仅输出角色名称或编号，技能之间恰好两个 ASCII 空格。Cost 使用十进制表示并去除尾随零。
- 清理名称首尾空白及会破坏分隔的换行、制表符等。正式内容只包含分组行。使用 UTF-8，行分隔使用 LF，非空正式文件末尾恰好一个 LF。事件的完整原始 Cost 仍保留于 JSON。
- 影响释放序列的候选或冲突未解决、角色未确认或组首 Cost 缺失时，拦截正式导出并提示对应审核项。未知恢复量按断组规则处理并标明审核状态。空分析的正式导出行为见设计中的待确认项。

```text
6c 星野  小春  亚子
5c 2  佳代子
4c 1
3.5c 6  3
```

**验收**　按字节对比样例及末尾 LF，覆盖整数、小数、空名回退、名称中的换行与制表符。未通过导出检查时仍可保存带审核信息的 JSON。

## 6. 跨电脑协作与质量验收

- Git 管理代码、文档、配置模板和允许共享的小型测试素材。个人路径、本地 `.env`、密钥、媒体及大型中间产物放在仓库之外或按规则忽略。交接记录写明环境、实际测试结果及依赖的数据。
- 核心自动化测试覆盖 FIFO、未知队列约束、修订重放、费用充足性、分组阈值、角色名称回退、Markdown 字节格式及 JSON 序列化。合成素材用于确定性回归。真实视频使用人工标注评估释放、角色、Cost 和分组，按视频或片段分离调试与评估数据，记录误差、漏检、误报和待审比例。量化通过线待样本基线建立后确认。

**验收**　另一台 Windows 电脑可根据仓库文档和本机 `BA_DATA_DIR` 配置复现已记录的验证，真实视频评估结果可回溯到标注和失败样本。
